## Runs and fixes

| Run       | Outcome                                                                                       | Fix                                                                                                                                         |
| --------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| a80, a80b | Proof failed at the ping warmup: the harness's Scene version only advanced on STATE_SYNC      | `v15WorkloadBrowser.ts` advances the socket's Scene version from Scene `COMMAND_COMMITTED` deltas                                           |
| a81       | Proof passed; budgets failed: about 21 MB per session, staged-checkpoint cleanup unclassified | Packed pages capped at the inline bound so they never staged                                                                                |
| a82b      | 13.0 MB; media cleanup jobs unclassified                                                      | Media and R2 cleanup jobs classed as background jobs                                                                                        |
| a83       | 15.5 MB (estimate now scaled by commands per fight); COMPLETE still split into 4 pages        | Staged route removed, every checkpoint inline up to 1 MiB (ADR 0035 Amendment 31); the 4 MiB raw journal read still cut each save           |
| a84       | Passed                                                                                        | The room streams journal pages into one fold, so a fight's save is one checkpoint and Run rows created and dropped in it never reach Convex |

Root cause of the excess: a fight's save split into prefix pages. Early pages inserted per-command Run
rows (rule occurrences, replay index, initiative participants, turn movements) that the last page then
read and deleted under Amendment 30, about 1.2 MB of reads per fight, and each page over 240 KiB was
staged (written, read back and deleted). Combat write sets hold whole documents, about 35 KB per
command, and fold about 16:1, so the 4 MiB raw journal read was the real limiter.

## Risks

- A save near the 1 MiB bound runs in one Convex mutation under its 1 s user-code limit; the largest
  measured save was about 300 KB of records.
- The fold is synchronous in the room: a fight's whole unsaved journal (about 15 MB raw at 424 commands)
  folds at COMPLETE in one pass. Previews were not measured during the save window.
- Budget headroom is thin (see above).
