## Findings

### 1 (red): the lifecycle skips four browser proofs

The lifecycle keeps its own hardcoded proof lists: `nativeProofModes` (`scripts/validatePreStagingLocal.mjs:676`) and `browserProofModes` (`:703`–`737`). The canonical proof list is the `-Proof` ValidateSet of `scripts/runLocalConvexProof.ps1:15`, and CI already reads it as the one source (`runnerProofs`/`ciProofsOf`, `scripts/affectedBrowserJourneys.mjs:123`–`132`). The two have drifted. The runner has 61 proofs, the lifecycle runs 57, and these four are in the runner (and CI) but never run in the final lifecycle:

- `shove-aside-browser`
- `held-effect-browser`
- `concentration-sheet-browser`
- `summon-turn-browser` (`scripts/runLocalConvexProof.ps1:65`)

All four of these journeys gate in CI, but R08 requires the "complete browser journeys" on the final source (runbook step 4), so as things stand RELEASE-2.T1 would pass without proving them. The same duplicated list is also why the drift went unnoticed: every new journey slice adds to the runner and CI automatically, and nothing makes it add to the lifecycle.

Proposed fix: build the lifecycle's proof stages from `runnerProofs(readFileSync('scripts/runLocalConvexProof.ps1'))`. Keep only the ordering rules local (native before browser, `selfManagedBrowserProof` = `vtt-browser` last) instead of a second list. This is one knowledge home, following DRY as AGENTS.md defines it.

Proposed regression test, in `scripts/validatePreStagingLocal.test.mjs` (it fails today with the four names above): read the runner's ValidateSet with the real `runnerProofs`, take the `-Proof` arguments of the lifecycle's stage list (export the stage list, or test the `--list` output), and require the two sets to be equal and `vtt-browser` to be the last proof stage.

### 2 (amber, not blocking): the account-deletion proof is named differently

`localProofStage` (`scripts/validatePreStagingLocal.mjs:740`–`743`) special-cases `account-deletion-browser`. It is named `account-deletion-browser<attempt>` (in this listing, `account-deletion-browsermw2i97wx`) instead of `r08-<attempt>-browser-<proof>`, because its driver requires the attempt to match `/^account-deletion-browser[a-z0-9-]{2,80}$/` (`apps/apis/tests/developmentDrafts.ts:5416`). It works, but the evidence lands outside the `r08-<attempt>-*` naming that the rest of the manifest uses, and it is the kind of named-proof special case AGENTS.md rules out. A cleaner fix would make the driver accept any `--fixture-attempt` name, as the other proofs do. This does not block T1.
