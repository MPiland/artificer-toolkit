# ADR 0038: Rules mechanics are authored from core options

- **Status:** transitional (user rulings 2026-10-14; 195 SRD closed rules remain until SPELLS-4 converts them)
- **Date:** 2026-10-14
- **Scope:** authored mechanics, `CLOSED_RULE`, Authoring Schema node maps, and Encounter zones (hazards and traps)
- **Update when:** a new authored discriminant is added (the `reactionTrigger` union, decision 7), a closed rule is kept on purpose, or zone placement or concealment changes
- **Supersedes:** the `CLOSED_RULE` guidance in [the engine guide](../architecture/engine.md) that a closed rule kind is "preserved unchanged for a future resolver"
- **Verification:** authoring-parity tests for each converted mechanic (an author-built record through the real form and publication equals the SRD record and resolves the same); the SRD corpus tests; the [Phase 8 ledger](../roadmap/08-phase-ledger.json) items SPELLS-4, SPELLS-25 and MOVE-3

## Context

Homebrew parity is the product promise: anything the SRD does, an author can build. Two shapes break it.

- **`CLOSED_RULE`** dispatches a whole SRD mechanic (Spike Growth, Wall of Fire, Moonbeam) to a named resolver. An author cannot build a variant, because the behavior lives in code, not content. The 2026-10-14 scan found 195 closed rules in the SRD corpus (154 spell, 41 equipment). SPELLS-4 had planned to give each a resolver, which would have hardened the gap.
- **Feature-specific engine shapes** (a Rage executor, a trap subject, an item category that switches rules) have the same effect.

The hazards and traps design (MOVE-3) tested the rule: caltrops, Blade Barrier and an environmental pit had to share one model without a trap-specific contract.

## Decision

1. **Core options only.** Every rules mechanic (class features, spells, items, hazards) is expressed with generic authored options that the Authoring Schema node map exposes. When an SRD mechanic cannot be expressed, add a generic option, never a feature-named kind, executor or SRD-only helper. Each such change carries an authoring-parity proof.
2. **`CLOSED_RULE` is retired.** No new closed rule kinds are added. Existing kinds are converted to core options and their kinds and resolvers deleted (SPELLS-4). Until then they stay fail-closed and manual, as today.
3. **Hazards come from content.** A `ZONE` manifest with an entry interaction is a hazard, whichever item, spell or feature places it. No item category or property marks a hazard, because one item can carry both a hazard effect and an unrelated one (ball bearings as sling ammunition).
4. **Every zone states where it is placed.** `attachmentKind` is required on `ZONE` (SPELLS-25). The runtime never infers placement from range or shape.
5. **Concealment is placement state, except authored camouflage.** A placed zone's optional spot DC and disarm DC belong to its Scene record and are set by the GM (MOVE-3.3). Content authors concealment only when its own rules camouflage it, through an existing DC method (MOVE-3.4). A concealed zone is redacted per viewer on the server.
6. **Environmental traps are Scene zones.** The GM zone tool renders the same zone node map as authored content (MOVE-3.2). There is no trap subject.
7. **A reaction names its trigger with a generic discriminated option.** `reactionTrigger` on an invocation is a union (`MOVEMENT`, `ATTACKED_SELF`, `DAMAGE_TAKEN` with its chosen damage types, `SPELL_CAST`; REACTION-4 adds more) that replaced the movement-only `reactionMovementTrigger`. It is a node-map group, so an author builds Shield, Opportunity Attack or a homebrew ward from the same options, and the engine never names a spell or feature. A reaction cast as an action is refused (`REACTION_TRIGGER_ONLY`). Authoring-parity proof for `ATTACKED_SELF`: `nativeRoomReaction.test.ts` runs the real SRD Shield and a homebrew +3 clone through the same pipeline. For `DAMAGE_TAKEN` it runs a user-authored Absorb Elements (`absorbElementsSpell`, not seeded content). A `DAMAGE_RESISTANCE` grant payload may name the triggering damage type (`damageTypeSource: 'TRIGGER'`) instead of a fixed one; the room binds it to the types the hit dealt when it plans the reaction's effect, so the authored shape carries no spell id and no per-spell rule. A hit offers every eligible reaction as a menu (one reaction a round, so one choice). The Counterspell rule is `SPELL_CAST` plus the `CANCEL_TRIGGERING_EVENT` outcome; the `COUNTERSPELL` closed-rule kind is deleted. A cast holds for the reactor's choice before its graph runs (D126), and the web authoring-parity gate round-trips the SRD Counterspell effects through the spell form.

## Consequences

- SPELLS-4 changes from "add resolvers" to "convert to core options", and grows by the generic options the conversions need (for example damage per distance moved, for Spike Growth).
- Workbooks for rules features require an authoring-parity proof, and reviews reject feature-named shapes.
- Node maps and schemas grow generic options instead of the closed-rule enum growing.
- Hazard behavior, half-speed bypass (`bypassAtHalfSpeed`, Q2's Move carefully) and save-on-entry are already core options (SRD Caltrops proves it). Placing spell zones waits on SPELLS-25.
- The 2024 rule variants (for example caltrops without a half-speed bypass) become System options later, not new kinds.
- Hide and Search (ATTACK-10.T1) are built from generic options: the `CONCEAL_FROM_OBSERVERS` and `DETECT_CONCEALED` effects, the `PASSIVE` and `CONCEALMENT` check DC kinds, and the `LOCATION_CONCEALMENT` state contribution. The parity proof is `packages/authoring/src/nodeRuntime/concealmentAuthoringParity.test.ts` (the SRD effects and a variant that checks another skill pass the effect node map unchanged) plus `packages/rules-runtime/src/__tests__/concealCompile.test.ts` (the SRD action compiles from the catalogue through the same options). See [the rules-runtime guide](../architecture/rules-runtime.md).
- Spirit Guardians (SPELLS-20 T1b) is a `SOURCE` `ZONE` built from the same options as any placed zone (a Wisdom save against the caster's spell save DC, radiant dice on failure, `ENTER_SPACE`); its closed rule kind is deleted. The parity proof is `packages/authoring/src/nodeRuntime/sourceZoneAuthoringParity.test.ts` (the SRD effects and a variant with another radius and a fixed DC pass the equipment effect node map unchanged), and the room journey is `apps/session-worker/test/nativeRoomSourceAura.test.ts`. See [the rules-runtime guide](../architecture/rules-runtime.md).
- The Balor's Fire Aura (SPELLS-20 T6c) is a Creature's passive zone built from the same options (a SOURCE `ZONE` acting at `START_OF_SOURCE_TURN` with fire dice and no save); its closed rule kind is deleted. The parity proof is `packages/authoring/src/nodeRuntime/creatureZoneAuthoringParity.test.ts` (the SRD feature and a variant with another radius and other dice pass the creature node map unchanged) plus `packages/rules-runtime/src/__tests__/encounterPassiveZones.test.ts` (it plans the same zone as a core-options aura), and the room journey is in `apps/session-worker/test/nativeRoomTurnZoneEffects.test.ts`.
- Melee-hit retaliation (SPELLS-20 T6d1, D153) is the zone interaction kind `MELEE_HIT_ON_SOURCE`, and a zone's placer may receive one timed grant authored beside the zone. The Balor's Fire Aura authors the kind; Fire Shield is a cast choice of two 5-foot SOURCE zones with a resistance grant. Parity: `packages/rules-runtime/src/__tests__/encounterZonePlacementCompilation.test.ts` (the Balor compiles as a core-options aura answering melee hits) and `encounterZoneChoiceCompilation.test.ts` (Fire Shield and a variant with other values compile accordingly), plus `sourceZoneAuthoringParity.test.ts` (Fire Shield passes the node map unchanged). With the runtime seam (T6d2a) Fire Shield's closed rule kind is deleted; `nativeRoomMeleeRetaliation.test.ts` proves both in the room, and (T6d2b) opportunity and Legendary Action attacks retaliate through the same generic step (`nativeRoomMeleeRetaliation.test.ts`, `nativeRoomLegendary.test.ts`).
- Ending held effects (SPELLS-4 T2f, D174) is the `END_EFFECTS` outcome (a scope of every match or one the caster picks, and the conditions it matches), authored from core options. Lesser Restoration, Greater Restoration and Protection from Poison compile from it and their closed rule kinds are deleted; the pick rides the cast command, the server derives the legal list, and an empty list is the overridable `TARGET_NOTHING_TO_END` warning. Parity: `packages/rules-runtime/src/__tests__/endEffectsAuthoringParity.test.ts` (SRD Lesser Restoration and a homebrew variant), with the room journey in `apps/session-worker/test/nativeRoomEndEffectsSpell.test.ts`. Remove Curse waits on the tag selector and Dispel Magic on T2f1.
- Source creature types on grants (SPELLS-4 T2j1, D179) is the facet predicate `SOURCE_CREATURE_TYPE` plus an optional `bypassedBy` on damage resistance and immunity payloads. Protection from Evil and Good, Purity of Spirit, Stoneskin and Wind Walk are authored from them and their closed rule kinds are deleted. Parity: `packages/authoring/src/nodeRuntime/sourceCreatureTypeAuthoringParity.test.ts` (Purity of Spirit and a variant for another creature type pass the class node map unchanged) and `packages/rules-runtime/src/__tests__/encounterSourceQualifiedGrants.test.ts` (the SRD spells' compiled grants admit only the authored types and bypass only by trait). See [the rules-runtime guide](../architecture/rules-runtime.md).
- Source traits and END_EFFECTS origin types (SPELLS-4 T2j2a, D183) add the facet predicate `SOURCE_TRAIT` and `originCreatureTypeIds` on `END_EFFECTS`. Holy Aura and Dispel Evil and Good's attack-disadvantage and save-advantage grants are authored from core options; their closed kinds stay until T2j2b and T2j2c. Parity: `sourceTraitAuthoringParity.test.ts`, `endEffectsAuthoringParity.test.ts`.
- Occupant save-bonus auras (SPELLS-20 T5a, D155) are the zone component option `occupantSaveBonus` (every saving throw, the source and its allies, a fixed amount or a source ability modifier with a minimum) on an untriggered SOURCE zone whose radius may scale by class level. The Paladin's Aura of Protection is authored from it and its closed rule kind is deleted. Parity: `packages/authoring/src/nodeRuntime/classAuraAuthoringParity.test.ts` (the SRD feature and a fixed-bonus variant with another radius pass the class node map unchanged) and `packages/rules-runtime/src/__tests__/encounterOccupantSaveBonusCompilation.test.ts` (it compiles as a core-options aura). Placement resolves the bonus and radius against the source (T5b); the save-time bonus lands in T5c.
- Removal from play (SPELLS-4 T2h1, D178) is the generic effect option `REMOVE_FROM_PLAY { keepsTurn }`. It compiles to a `PLAY_ABSENCE` state contribution held by the effect, so the holder's `absence` (`EFFECT` or `EFFECT_KEEPS_TURN`) is recomputed from the removals it still holds at the effect-store seam, on create and on every delete path (end, Undo, dismissal); `GM_REMOVED` and `DEPARTED` are never overwritten or cleared by it. Every absent actor is untargetable and caught by no area. Etherealness, Imprisonment and the removal half of Maze are authored from it, and the closed rule kinds of Banishment, Etherealness, Imprisonment and Maze are deleted. Banishment's save-gated incapacitate-plus-removal sequence, Etherealness and Imprisonment compile from the same options (T2h4); a return onto an occupied space is flagged `RETURN_SPACE_OCCUPIED` for the GM to place by hand (D184), and Blink and Maze's escape stay as they are (T2h2, T2h3). Parity: `packages/authoring/src/nodeRuntime/removeFromPlayAuthoringParity.test.ts` (the SRD effects and a variant that keeps the turn pass the effect node map unchanged), with persistence in `packages/encounter-persistence/src/__tests__/playAbsencePersistence.test.ts` and area and target admission in `encounterAreaActionExecution.test.ts` and `encounterActionTargetPolicy.test.ts`. See [the rules-runtime guide](../architecture/rules-runtime.md).
