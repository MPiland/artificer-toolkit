# Slice ATTACK-2.T1 and T2: player play parity

Workbook rules: [slice-workbook-rules.md](slice-workbook-rules.md).

## Scope

- T1 closes part of AC ATTACK-2.5 (a player can do everything the GM can for their own Characters in play; launch-gating, ADR 0034 inventory section 7). Build a parity matrix test derived from the real Encounter command registry, not a hand-written list: every command the GM can issue for a Character is accepted from that Character's controlling player (own actor; own turn or an open reaction window) and refused for another player's or an uncontrolled actor. Each GM-only gap the matrix finds is fixed through the player path, never by widening authorization. Commands that are legitimately GM-only (adjudication, reveal, undo) are listed with the decision that makes them GM-only.
- T2 (after ATTACK-2.T1, ATTACK-17.T3 and REACTION-4.T3b) closes the rest: a browser journey on the player client in which a player, on their own Character, casts an area spell, takes a death save, uses a non-movement reaction and targets from the map, with no GM step.

## Log

- T1 matrix: `apps/session-worker/test/nativeRoomPlayerParity.test.ts`. Command types come from `encounterCommandInputDtoSchema` and `encounterActorTokenBindingCommandInputDtoSchema` (30 types); a drift test fails when a type has no class, and pins the PLAYER and SHEET lists. Three classes (Phase 8 ruling): **PLAYER** (the controller is treated as the GM is; another player and an uncontrolled actor are refused), **SHEET** (the Sheet command owns it; the Encounter command stays `GM_ONLY` for players, and the row proves the player's Sheet path in a live Encounter and its refusal for another player) and **TABLE** (Encounter administration, outside AC ATTACK-2.5; the player is refused `GM_ONLY`; each row cites its rule plus the AC scope). Refusals assert the Run version is unchanged.
- PLAYER: `ROLL_ACTOR_INITIATIVE`, `ADVANCE_TURN`, `RESOLVE_ACTION`, `ROLL_RULE_EVIDENCE`, `RESOLVE_RULE_OCCURRENCE`, `ESCAPE_RELATIONSHIP`, `END_HELD_GRANT`. Another player's `ROLL_RULE_EVIDENCE` reads `DECISION_NOT_PENDING`, because a decision the player is not party to is hidden from them (ADR 0034 pending reads).
- SHEET: `ADJUST_FEATURE_RESOURCE` (covered by Sheet `USE_RESOURCE` and `RESTORE_RESOURCE`, both in `ROOM_CHARACTER_PLAY_COMMAND_TYPES`; the live proof sends the Sheet's `ADJUST_HIT_POINTS` as the player).

AGENTS.md "Builder owns structural character changes" plus D87: UPDATE_ACTOR. `SET_INITIATIVE` is TABLE once the order is settled.
- Gap found and fixed: `ROLL_ACTOR_INITIATIVE` and `SET_INITIATIVE` hit the blanket `GM_ONLY` gate in `recordEncounterToolCommand` (red CI run 38867191155). Now the controller (`requireEncounterActorControl`) may roll for their own actor; may enter their own value only while the Run is `PREPARED` and with no `manualOrder`. The command now returns `presentEncounterResultForMember` so a player never gets the GM projection. Proof against the real room executor: `apps/session-worker/src/roomEncounterPlayerInitiative.test.ts` (own actor accepted, another player's and an uncontrolled actor `NOT_ACTOR_CONTROLLER`, `manualOrder` and the settled order `GM_ONLY`). The PREPARED room is `src/testing/preparedEncounterRoom.ts`, shared with `roomEncounterInitiativeResponse.test.ts`.
- Risk: `ROLL_ACTOR_INITIATIVE` has no status window (Phase 8 ruling), so a controller can re-roll their own initiative in an ACTIVE Run. The roll posts to the table and reaches the GM, as the GM's own roll does; registered for a ruling if the window should close.
