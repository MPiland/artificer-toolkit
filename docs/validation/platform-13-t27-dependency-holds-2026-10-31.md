## First-use schema cost probe

`apps/apis/scripts/liveBackendSchemaProbe.ts` runs in the Live backend `schemaCost` step right after the deploy. It calls `content/schemaCostProbe:parseDocument` with the largest SRD document of each kind and fails if a cold call passes 500 ms. Numbers are client round trips, not in-function time (live backend run, zod 4.5.3 tip):

| Kind       | Size    | Cold  | Warm | First-use |
| ---------- | ------- | ----- | ---- | --------- |
| BACKGROUND | 12 KiB  | 36 ms | 2 ms | 34 ms     |
| CLASS      | 154 KiB | 48 ms | 2 ms | 46 ms     |
| CREATURE   | 29 KiB  | 52 ms | 2 ms | 50 ms     |
| EQUIPMENT  | 7 KiB   | 43 ms | 2 ms | 41 ms     |
| FEAT       | 2 KiB   | 30 ms | 2 ms | 28 ms     |
| RACE       | 45 KiB  | 28 ms | 1 ms | 27 ms     |
| SPELL      | 31 KiB  | 27 ms | 1 ms | 26 ms     |
| VEHICLE    | 1 KiB   | 15 ms | 1 ms | 14 ms     |

The probe covers publication-document parsing only; it did not reproduce the sheet-path timeouts, which parse other schemas.
