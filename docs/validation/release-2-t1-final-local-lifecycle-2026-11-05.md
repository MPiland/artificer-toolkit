### Handoff: Storybook e2e cold start (for the Storybook e2e CI follow-up slice)

**Symptom.** The first test of the Playwright `storybook` project runs against a cold `storybook dev` server and sits close to the 30 s test timeout: 40.4 s in run P (it passed only because that test's timeout was 60 s), 33.1 s in run Q2 (failed). It is structural, not a flake: every cold start pays for compiling the first story's module graph inside the first test.

**Trace timings (run Q2, `local-validation/pre-staging/r2t1-q2/web-e2e.log`).** The trace (`apps/web/test-results/authoringWalkthrough-route-f7670-*/trace.zip`) was later overwritten by the static-build proof; these timings were read from it first.

- `webServer` readiness (`http://127.0.0.1:6006` answers) passes before any story module is compiled.
- `goto` reaches `load` at 62.9 s.
- Vite then transforms about 2,000 modules on demand; `AuthoringLayout.css.ts` alone takes 22 s.
- The last module request starts at 91.0 s; the 30 s canvas expectation in `openStory` (`authoringWalkthrough.spec.ts:333`) expires at 93.0 s; "Mocking enabled" logs at 93.1 s.

**Why ruling (A) failed.** (A) served the Storybook projects from a static `storybook build` through `vite preview` (port 6008). In the build, `sb.mock` is not applied (Storybook 10.6.5, Vite 8.3.5): `.storybook/preview.tsx` mocks `convex/react`, `convex-helpers/react` and `vttSceneRenderer.ts` with `sb.mock` (lines 25-27), and its global `beforeEach` (line 102 onward) calls `mocked(useConvexAuth).mockReturnValue(...)`, which throws on the real module. Every story failed with `TypeError: Z6(...).mockReturnValue is not a function at beforeEach (http://127.0.0.1:6008/assets/iframe-BblH1b7o.js:1130:39302)`. Evidence: `local-validation/release-2-t1/storybook-static-proof.log` and `apps/web/test-results/authoringWalkthrough-route-*/error-context.md`. The config change was reverted; `apps/web/playwright.config.ts` is unchanged on this branch.

**Lead option (C).** Keep `storybook dev` and warm the story graph before the first test: Vite's `server.warmup.clientFiles` for the story files and preview entry in `.storybook/vite.config.ts` (or `viteFinal`), and a Playwright readiness URL that answers only once warm-up has finished. **Open question:** whether Vite's warm-up can be awaited from outside (a signal, endpoint or hook that resolves when the warmed transforms finish). If it cannot, warm-up only shortens the race and does not remove it; then a readiness probe that itself requests and waits for the first story's iframe graph is the fallback to evaluate.

**Alternative (A2).** Keep the static build and replace `sb.mock` automocking with mocks that survive a build (for example explicit module aliases to mock files). This changes how every story mocks Convex, so it is larger than (C).

### Runs O and O2: Storybook files failed to load about 5 minutes in

Both runs failed at `web-storybook-tests` on the same source, `7c605ddb7`. Each time, 66 of 67 story files passed and one could not load a module:

- **Run O** (`local-validation/pre-staging/r2t1-o/web-storybook-tests.log`): `FeatCreateRoute.stories.tsx > Create Empty` failed with `TypeError: Failed to fetch dynamically imported module: …/node_modules/.vite/storybook/deps/axe-core.js`. The stage started at 10:55:28 and the story ran at about 11:00:37, 5m09s in. MSW's start banner ("Worker script URL … Worker scope … Client ID … (nested)") appears exactly once in the log, immediately before this story.
- **Run O2** (resumed from the stage, `r2t1-o2`): `EquipmentCreateRoute.stories.tsx` failed to import, with `Failed to fetch dynamically imported module: …/EquipmentCreateRoute.stories.tsx?import`. The stage started at 11:03:30 and the import failed at about 11:08:56, 5m26s in.

**Cause (verified):**

- **Upstream bug.** In mswjs/msw#2801, "Worker stops intercepting requests after ~5 minutes in Chromium", the generated `mockServiceWorker.js` awaits `sendToClient()` replies the client never sends, for KEEPALIVE_REQUEST, INTEGRITY_CHECK_REQUEST and MOCK_ACTIVATE, inside `event.waitUntil()`. Chromium terminates a worker whose event is still pending after 5 minutes. The restarted worker has an empty `activeClientIds`, and a test file loading at that moment fails with `Failed to fetch dynamically imported module`, as one commenter reports for Vitest browser mode.
- **Fix.** msw v3.0.4 (2026-11-06, "worker: prevent the worker from going idle", #2830) replies without awaiting, and stores the active clients in Cache Storage so that a restarted worker restores them.
- **Our worker.** The worker this repo served, `apps/web/public/mockServiceWorker.js`, was `PACKAGE_VERSION = '3.0.2'` with exactly that awaited code (lines 35, 86, 93 and 106). `yarn add` reported the resolved package moving from `msw@npm:3.0.3` to `3.0.4`.

**Fix:** `a7cb52915` upgrades msw to `^3.0.4` and regenerates the worker. msw-storybook-addon's peer range needed no change.

**Red proof:** `apps/web/src/test/msw/MockServiceWorker.stories.tsx` is a Vitest-only story in the CI `storybook` suite. It stops every service worker through CDP (`ServiceWorker.stopAllWorkers`, the `stopServiceWorkers` command in `apps/web/vitest.config.ts`), then asserts that a request the story mocks is still mocked.

- **On the 3.0.2 worker:** red, because the request bypassed the worker (content-type `null`). That run asserted with `toContain`; the committed `toBe` fails the same way on `null`.
- **On 3.0.4:** green.

What the proof does and does not cover:

- It proves the lost-clients defect. 3.0.4 also removes the cause of the termination itself, the event that never settles.
- It does not reproduce the 5-minute idle kill. That needs a run of more than 5 minutes per test.
- It does not reproduce the exact in-flight import failure. The fresh full run is the end-to-end check.
